Treeframe turns any public GitHub repository into an animated folder map that you can drop into your README. Paste the repository link, tweak the result visually if you want, and embed a short link instead of a giant block of SVG code.

The project started from a simple frustration: folder structures pasted as plain text in READMEs are hard to read and never explain what each folder is for. Treeframe generates a clean, themed and animated map, with an optional description for every folder.

> [!NOTE]
> The map is generated automatically from the repository link alone. To customize it, commit a `.treeframe.json` file to the root of your repository. Both modes are described below.

## Project Overview

Treeframe has two parts that work together:

* **SVG generator:** a framework-free TypeScript library that receives a list of paths plus a config and returns a self-contained animated SVG.
* **Website:** a Next.js app that reads the repository through the GitHub API, serves the SVG on a short link, and provides a visual editor to customize the map.

The recommended flow is layered and needs no database and no login:

1. Paste a repository link and get a ready-made map in seconds.
2. Refine it in the editor: hide folders, add descriptions, pick branch colors, depth and theme.
3. Download the generated `.treeframe.json` and commit it to your repository.
4. Paste the Markdown snippet into your README.

If the config file does not exist, the map is generated automatically with sensible defaults, so the link never breaks.

## Endpoints

### 1. Map — `/api/map`

**Description**

Returns the folder map as `image/svg+xml`. This is the link you embed in your README.

**Endpoint**

```http
GET /api/map?repo=owner/name
```

**Query parameters**

| Parameter  | Description                                  | Example           |
| ---------- | -------------------------------------------- | ----------------- |
| `repo`     | Repository as `owner/name` or a GitHub URL   | `vercel/swr`      |
| `branch`   | Branch or tag (default: the default branch)  | `main`            |
| `depth`    | Folder levels to show, from 1 to 6           | `3`               |
| `theme`    | `dark` or `light`                            | `light`           |
| `title`    | Custom name for the root folder              | `my-project`      |
| `files`    | `0` hides files and shows only folders       | `0`               |
| `comments` | `0` hides the folder descriptions            | `0`               |

Query parameters override the values from `.treeframe.json`.

**Example**

```markdown
[![Treeframe](https://tree-frame.vercel.app/api/map?repo=vercel/swr&depth=2&theme=light)](https://tree-frame.vercel.app/r/vercel/swr)
```

### 2. Interactive page — `/r/owner/name`

**Description**

Shows the same map inline, where the hover effect works. This is where the README image links to, since GitHub displays SVGs as plain images and does not forward mouse events.

### 3. Editor helpers — `/api/tree` and `/api/preview`

**Description**

Internal endpoints used by the visual editor. `/api/tree` lists the folders of a repository, and `/api/preview` renders the map with the configuration currently in the editor.

## Configuration

Commit a `.treeframe.json` file to the root of your repository. Every field is optional.

```json
{
  "title": "my-project",
  "depth": 3,
  "theme": "dark",
  "showFiles": true,
  "showComments": true,
  "ignore": ["legacy", "*.snap"],
  "hide": ["src/internal"],
  "descriptions": {
    "src/api": "External API integrations"
  },
  "colors": {
    "src/api": "#ffe14a"
  }
}
```

| Field          | Description                                                      |
| -------------- | ---------------------------------------------------------------- |
| `title`        | Name shown for the root folder                                   |
| `depth`        | Folder levels to show (1 to 6)                                   |
| `theme`        | `dark` or `light`                                                |
| `showFiles`    | Show files besides folders                                       |
| `showComments` | Show the descriptions next to each entry                         |
| `ignore`       | Extra names or patterns to skip (`name`, `*.ext`, `path/to/dir`) |
| `hide`         | Paths to hide, together with everything inside them              |
| `descriptions` | Description per path                                             |
| `colors`       | Hex color per path                                               |

Noise such as `node_modules`, `.git`, `dist` and lockfiles is ignored by default. Common folder names (`src`, `public`, `tests`, `docs`...) get a default description when you do not write one.

## Architecture

This is the folder map of the repository itself, generated by Treeframe:

[![Treeframe](https://tree-frame.vercel.app/api/map?repo=Glauedson/TreeFrame)](https://tree-frame.vercel.app/r/Glauedson/TreeFrame)

The project is split into two independent packages inside one repository. The generator knows nothing about the web, and the website knows nothing about how the SVG is drawn. Data flows in one direction:

```
GitHub API  →  server/services  →  svgGen  →  /api/map  (image/svg+xml)
```

**SVG Generator (``svgGen/``)**

>A pure library: it receives a list of paths and a config, and returns the SVG string. It has no I/O and no framework. Internally it is organized as a pipeline of small modules: `domain` for shared types, `config` for defaults and validation, `theme` for colors, `tree` for filtering, sorting, describing and coloring, `layout` for rows and coordinates, and `render` for the final markup.

**Server (``front-end/src/server/``)**

>Talks to the outside world. The GitHub client fetches the whole tree in a single request, the services combine it with the repository config and call the generator, and the HTTP helpers shape responses and cache headers.

**App (``front-end/src/app/``)**

>Pages and API routes, kept thin: each route parses its input, calls a service and returns the response. The interactive page `/r/owner/name` lives here as well.

**Features (``front-end/src/features/``)**

>The visual editor, split into small components and hooks for the repository form, settings, folder list, live preview and export panel.

**Shared (``front-end/src/lib/`` and ``front-end/src/components/``)**

>Small helpers and reusable pieces used across the website, such as the repository link parser and the copy button.

**Security**

>Config files come from arbitrary repositories, so they are treated as untrusted input. Every field is validated, colors must be hex values, text is length-limited, and everything is XML-escaped before it reaches the SVG.

**Caching**

>Responses are cached on Vercel with `s-maxage`. GitHub also caches README images through its own proxy, so a changed map can take a little while to show up.
